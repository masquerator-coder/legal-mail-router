📎 多附件分组分析

含多附件的邮件先分组再逐组分析
启用后，系统会先由 LLM 判断哪些附件属于同一份独立文书，再逐组进行法律分析。 适用于一封邮件包含多份不同合同/文书的场景。会增加少量 LLM 调用用于分组判断。 分组模型在「LLM 配置」页的角色分配中指定。

📝 修改版文书生成

LLM 分析后自动生成修改版文书
启用后，系统会在 LLM 分析完成后用审核意见对原文书进行修订，生成「修改版文书.docx」作为附件随邮件转发。会增加一次 LLM 调用。
在 Word 文档中用颜色标注修改内容
■ 蓝色 = 新增    ■ 红色 = 修改    ■ 删除线 = 建议删除   关闭则以纯文本输出。

📋 审核意见模板

用 DOCX 模板生成审核意见
启用后，系统将使用指定的 DOCX 模板替换 xxx 占位符， 生成「审核意见.docx」作为附件转发。
相对于项目根目录的路径。模板需为 .docx 格式，其中的 xxx 将被替换为实际信息。 模板示例：
P1: "...收到xxx发来的拟与xxx签订的《xxx》。合同内容为xxx事宜。合同价款xxx元。"
P6: 日期自动替换为当前日期

🔗 MCP 工具（法律检索）

第二阶段文书分析时，LLM 可调用 MCP 工具实时查询法律法规
启用后，LLM 分析文书需引用法规时，可调用工具查询「北大法宝」等权威数据库，并依据返回的条文原文引用；报告与修改版文书末尾会附加来源链接。工具不可用时自动降级，不影响正常分析。
已预填北大法宝 9 个服务器；Token 为占位符 __PKULAW_TOKEN__，请替换为你的真实 Token 后保存并「列出可用工具」验证。也支持 mcpServers 对象、服务器列表、名称映射字典三种形态。
模型通常需多轮检索法规后才输出最终 JSON，建议 ≥5（越大越易收敛但越慢；失败会自动回退为普通分析）。
